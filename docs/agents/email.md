# Email (#300)

Full reference, moved verbatim from AGENTS.md. The always-on rules for this area are summarised in AGENTS.md; this file holds the detail, the measurements and the history behind them.

- **Email is off unless `RESEND_API_KEY` is set and a sender can be resolved** (`emailEnabled()`, `src/lib/email.ts`). Unset means nothing is sent and **nothing fails** — the self-hoster default, with tests at the leaf and at the route. **Turning email on also registers magic-link sign-in and removes the shared password** (see Auth); a self-hoster who adds a key gets both, by design. The key and `RESEND_EMAIL_DOMAIN` are set on the Vercel project by the Resend Marketplace integration.
- **`src/lib/email.ts` is a leaf** (no app imports) and calls Resend's HTTP API with plain `fetch`, not the SDK: it is one POST, and `scripts/beta-pass.mjs` cannot import TypeScript, so it makes the identical call. If you change the request in one, change the other.
- **The sender is configuration.** `EMAIL_FROM` wins; otherwise it is `Flatpare <hello@<RESEND_EMAIL_DOMAIN>>`. `EMAIL_REPLY_TO` is optional. The From domain must be one Resend has verified, or every send is refused.
- **What an email may contain is a privacy decision** (the words are per language since #288; see Languages):
  - **Household invitation**, sent by `POST /api/invitations` after the row is created (`sendInvitationEmail`, `src/lib/household-email.ts`; words in `src/lib/email-templates.ts`). It carries the inviter's display name and a link to the site. **It does not carry the household's name**, and a route test asserts that. The invitee's address was already stored in plaintext by the invitation itself, so the email discloses nothing new to the server.
  - **Beta invitation**, sent by `node scripts/beta-pass.mjs create --email <address> [--locale de]`. The address is used for that one message and is **not stored**; `beta_passes` has no email column.
- **A failed send never undoes anything.** The invitation or pass is created first. The route answers `emailed: "sent" | "failed" | "off"` and the settings page says which, so an owner is not left assuming a message went out; the script prints the link regardless and exits 1.
- **`sendEmail` logs the HTTP status or the error's class and nothing else** — never the recipient, the subject, the key or the provider's message, which can quote the request back. Same posture as the process routes; pinned by `email.test.ts`.
- **`INVITATIONS_PER_DAY = 20` per household, only while email is on** (`assertInvitationBudget`, 429). Inviting mails an address the owner typed, and `MAX_MEMBERS` does not bound that: a revoked invitation frees its slot, so invite-revoke-invite could mail strangers from our domain without limit. Rows in every status count, because each one sent an email.
- **A display name is attacker-chosen.** `safeName` strips line breaks (it reaches the subject) and caps the length; `escapeHtml` covers the body.
- **Idempotency keys** are `household-invitation/<id>` and `beta-invite/<code>`; Resend deduplicates on them for 24 hours.
- **Beta request** (#301), sent to `BETA_REQUEST_NOTIFY_EMAIL` — the owner, not the requester — by `POST /api/beta-requests` for a new address (`notifyOwnerOfBetaRequest`). Carries the requester's address (escaped; kept out of the subject) and the two script commands to answer it. Idempotency key `beta-request/<id>`.
- **Member removed** (#298), sent by `DELETE /api/household/members/:id` after the removal commits (`sendMemberRemovedEmail`). Names who removed them, says access ended and the account is unchanged; nothing about the household. The route answers `200 { emailed }` (it was `204`) and the Household page says which.
- **Feedback** (#476), sent to `FEEDBACK_EMAIL` by `POST /api/feedback` (`sendFeedback`, `src/lib/feedback.ts`) from **Send feedback** in the user menu (`FeedbackDialog`). Members only; **stored nowhere**. Named feedback carries the sender's display name and address with Reply-To set to them (`EmailMessage.replyTo`, which wins over `EMAIL_REPLY_TO`); **anonymous carries the message, the app version and the interface language and nothing else** — no name, address, household or page path, since an apartment id in a path identifies the household. The route test asserts the absence. `FEEDBACK_PER_DAY = 100`, site-wide, counted in `feedback_days` by one conditional upsert; over it is 429. Without `FEEDBACK_EMAIL` or with email off there is no menu item and the route is 404 (`feedbackEnabled()`, passed as `feedback` to `NavBar` from the server components). The message never reaches a log: validation errors answer a fixed message, everything else logs under a `process:` tag. Idempotency key `feedback/<random uuid>`. English, an operator message. The terms page and the guide say what happens to it; change them with it.
- Not built: any admin UI for beta invitations — the script is the door, as before.
