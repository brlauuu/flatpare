# Blind proxies (E4)

Full reference. The rules for this area are in `.claude/rules/blind-proxies.md` (loaded when working on its files), with anything cross-cutting in AGENTS.md; this file holds the detail, the measurements and the history behind them.

- **Rate limiting.** `consumeRateLimit(householdId, endpoint)` (`src/lib/rate-limit.ts`) runs immediately after `requireMember()` in all six `/api/process/*` handlers — **before** the outbound call, since the point is bounding spend. Fixed one-hour windows in `process_usage` (migration 0016), one atomic `INSERT ... ON CONFLICT DO UPDATE ... RETURNING count`, so concurrent requests cannot both read "4 of 5". Over the limit is `429 { error: "Rate limit exceeded" }`.
  - `PROCESS_RATE_LIMIT_PER_HOUR` **unset or empty means unlimited** — the self-hoster default, since `docker compose up` must work unconfigured and a self-hoster spends their own keys. Anything that is not a positive integer throws `EnvConfigError` (`src/lib/env-int.ts`, via the shared `readOptionalPositiveInt`) rather than being coerced.
  - **Every call is counted, limit or not** (#413): the count is also the host's record of how many calls each household made, to compare with what it paid for (`credit_spends`, see Processing and credits). Only the refusal depends on the variable.
  - `process_usage` is one of the three tables a process route may write; the others are `apartment_charges` and `credit_spends` with the household's credit counter, only when billing is on (#413). It holds a household id, an endpoint name, an hour bucket and a count — no request content. A migration test asserts the column list so a future column is deliberate, and `no-leak.test.ts` leaves it out of the row counts it compares for that reason.
- **Log scrubbing.** `apiErrorResponse` logs only `scrubbedErrorLine(err)` (error class + numeric status, `src/lib/log-scrub.ts`) when the tag starts with `process:`; every other tag still logs the full error. **Never log an error's message, stack or cause from a process route** — a fetch failure's message is the outbound URL, and geocode's URL carries the address and `GOOGLE_MAPS_API_KEY` in its query string. That was a real leak, fixed here.
- **Outbound URLs are validated, not trusted.** `assertPublicHttpUrl` (`src/lib/safe-url.ts`, a leaf with no app imports) gates `checkListingUrl`: http(s) only, private/loopback/link-local/CGNAT/multicast/IPv6-ULA all refused, redirects walked by hand five hops deep with **every hop re-validated** (`redirect: "follow"` only ever checks the first URL). Anything that makes an outbound request on a user's behalf must go through it.
- **Address suggestions (#480)** for a location of interest, while typing, like a maps site: `POST /api/process/address-search` (`suggestPlaces`, `src/lib/places.ts`) asks **Google Places Autocomplete (New)** and `POST /api/process/address-place` (`resolvePlace`) asks Place Details for the picked one's `formattedAddress,location` only (the Essentials field mask; anything more costs more). Both calls carry the session token the browser minted for that search (`newRowId()`, renewed after each pick), which is how Google bills them as one search: suggestions free, the pick as one Place Details call. **It needs Places API (New) enabled on `GOOGLE_MAPS_API_KEY`**; until it is (a 403), or without the key, suggestions come from the geocoder instead (`searchAddresses` in `src/lib/geocode.ts`: Google Geocoding's one best match, or OpenRouteService's), each with its coordinates, so nothing breaks meanwhile. Suggestions favour the household's own area: `searchBias` (`src/lib/address-bias.ts`) sends the middle of its geocoded places rounded to a tenth of a degree, as a 50 km bias, never a restriction. The field is `AddressSearchInput` (`src/components/address-search-input.tsx`, an ARIA combobox: 3 letters, 300ms pause, arrow keys, Enter, Escape). Locations only, never apartments (decided on the issue: an apartment's geocode is its paid first processing). Free, and counted under their own `address-search` and `address-place` endpoints, so the usage report's geocode count, which it weighs against credits, stays the apartments' own. A picked place saves its coordinates, and `geocodeLocation` in the store does not geocode a location that already has them; `updateLocation` drops coordinates left over from the old address before deciding.
- **The listing search (#409) runs inside `/api/process/parse-pdf`**, not as a fifth route (`src/lib/find-listing.ts`). When the PDF's link is missing or `checkListingUrl` says it is gone, the AI model searches the web with the listing's title, address, website and language (the last two are read by the extraction as hints and never sent to the browser) and the first link not known to be gone replaces it; a link that cannot be checked is kept without searching, and when nothing is found the PDF's link stays, dead or not (decided on the issue). The client sends `searchListing=0` when the person brought a link (a share), which wins anyway. The search follows `AI_PROVIDER`: **`gateway` uses Google's Web Grounding for Enterprise** (`google.tools.enterpriseWebSearch`, documented as neither logging nor storing customer data; with ZDR on, the gateway routes Gemini to Vertex), **`google` uses Grounding with Google Search** under the Gemini API terms. Do not swap in Perplexity, Exa or Parallel on the hosted deployment: none of them states zero retention, and the gateway does not extend ZDR to tools. Google returns its own expiring redirect links as sources; they are resolved one hop through `assertPublicHttpUrl`. A failed search logs `scrubbedErrorLine` only and the extraction still answers. The review card says when a link came from the search, so the person checks it before saving. It costs one paid search per PDF without a working link and counts under the `parse-pdf` rate limit. The privacy section's `exceptionSearch` and the guide's privacy paragraph describe it.
- **The negative assertions live in `src/app/api/process/__tests__/no-leak.test.ts`** — all six routes, success and failure, marked plaintext, every console channel captured, every table's row count compared to a baseline. Its serializer expands an Error's message/stack/cause on purpose: `JSON.stringify(new Error("secret"))` is `"{}"`, so the naive version of that assertion passes no matter what leaks.
