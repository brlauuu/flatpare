# Drafts (#190), retired by #413

Full reference. The rules for this area are in `.claude/rules/drafts.md` (loaded when working on its files), with anything cross-cutting in AGENTS.md; this file holds the detail, the measurements and the history behind them.

- **A draft was a listing link saved to add later.** Since #413 a pasted or shared link becomes an **unprocessed apartment** instead (`createApartmentFromLink` in the store, `apartmentFromLink` in `src/lib/household-data/links.ts`: named after the title or the host, the link kept, `processed: false`), which is just as free. Nothing creates a draft any more: `POST /api/drafts`, the "To add" strip and `/apartments/new?draft=<id>` are gone. Design of the original: `docs/superpowers/specs/2026-10-27-pwa-design.md`.
- **The drafts left are turned into apartments by the store** (`adoptDrafts` in `src/components/household-data/drafts.ts`), after every load, from whichever member's device loads first: each becomes an apartment **with the draft's id**, then the draft is deleted. A `409 Duplicate id` means another device (or an earlier load whose delete failed) made it already, so the draft is just deleted. Any other failure, the apartment cap included, leaves the draft for the next load. A draft that cannot be opened stays where it is. The apartment records whoever saved the draft as `addedBy` (#430); drafts converted before 0.31.0 lost it.
- **What remains of the table**: `apartment_drafts` (migration 0025), `GET /api/drafts` and `DELETE /api/drafts/:id` (`requireMember()`, 404 for unknown and foreign rows), and rotation, which still re-seals drafts with everything else (`runRotateDataKey` sends `drafts`; the request's `drafts` defaults to `[]`, so a client that omits the set while drafts exist is refused as Stale rows). `MAX_DRAFTS` (`src/lib/draft-limit.ts`) now only bounds that request. Once no household holds a draft, all of it can go in a later release with a migration that drops the table.
- **The person's link wins over the PDF's.** A share with one PDF saves the share's link, not the one the extraction found (often dead, #409); with several PDFs the link fills only forms without one, since nobody knows which PDF it belongs to (`withSharedUrl` in the add page).
