# Public access gate and beta passes (#239, #240)

Full reference. The rules for this area are in `.claude/rules/public-access-and-beta-passes.md` (loaded when working on its files), with anything cross-cutting in AGENTS.md; this file holds the detail, the measurements and the history behind them.

- **`FLATPARE_PUBLIC_ACCESS=closed` closes sign-UPS, not sign-INS.** Read by `readPublicAccess()` (`src/lib/public-access.ts`, zero imports). **Unset, empty or `open` means open** — the self-hoster default, with a test, like every other unset-means-unlimited switch; anything else throws `PublicAccessConfigError` rather than being coerced, since a typo silently opening the door is the worse surprise. It is a runtime switch on purpose: no "coming soon" branch, nothing commented out. Decided on #239: the landing page stays visible (it explains the product and the price to the very people being asked to wait); only unrestricted account creation is blocked.
- **The enforcement point is Auth.js's `signIn` callback** (`authCallbacks.signIn` in `src/auth.ts` → `decideSignUp` in `src/lib/sign-up-gate.ts`), **not the proxy.** `@auth/core` runs `callbacks.signIn` *before* it creates a user row for a first-time OAuth sign-in (`handleAuthorized` precedes `handleLoginOrRegister` in `lib/actions/callback/index.js`), so a refusal leaves no stray account; and until the provider answers nobody knows whether the address is new, so the proxy cannot make this decision. A refusal returns the string `"/?signin=closed"`, which Auth.js's default `redirect` callback resolves against the origin — the landing page reads the query and explains, instead of the generic `AccessDenied` page.
- **What gets through when closed, in order:** (1) an existing account, always — the gate is about creation, never access; (2) a usable beta pass in the `flatpare_beta_pass` cookie; (3) a pending, unexpired invitation for the address — someone already in has vouched for them, which is the same act as handing out a pass, and without it a tester could not invite their partner. A provider profile with no email is refused when closed (it cannot be matched to an account) and allowed when open. `cookies()` throwing outside a request scope reads as "no pass", never as a way in.
- **Beta passes are the one door, and the same mechanism #240 grants credits through** (decided on both issues: two access systems that must agree are how they come to disagree). Tables `beta_passes` (code, label, credits, max_uses, uses, expires_at, revoked_at) and `beta_pass_redemptions` (one row per user) from migration 0019; both plaintext — the host's record, not user data, and deliberately **not** the `payments` ledger, which is keyed by Stripe event id and reconciles against Stripe. `src/lib/beta-pass.ts` holds the store; `GET /beta/<code>` (`src/app/beta/[code]/route.ts`, allow-listed in `src/proxy.ts`) checks the pass is usable, sets the httpOnly cookie for 24h and redirects to `/?beta=ready` (or `/?beta=invalid`, never echoing the code).
  - **A use is consumed when the pass admits a NEW account, not when the link is opened** — `consumeBetaPassUse` is one guarded `UPDATE ... WHERE uses < max_uses` (an 8-way concurrency test pins exactly 3 of 8 through a three-use link; not a `db.transaction`, see #225). It is consumed **open or closed**: the use count and the redemption row are what #240 keys the free credits on, so they must be honest regardless of whether the door happened to be locked. `events.createUser` then records the redemption (`recordSignUpPass`). A use consumed for a sign-in that then fails is lost; accepted.
  - **Revocation stops the link, never the people** (decided on #240): `revokeBetaPass` touches `revoked_at` only. Nothing granted through a pass is ever clawed back, and there is no expiry on access conferred — only on the pass.
  - **Minting is `node scripts/beta-pass.mjs create|list|revoke`**. The script loads `.env.local` itself (a shell value wins, so `TURSO_DATABASE_URL= node scripts/beta-pass.mjs ...` forces the local file, same rule as the app) and prints which database it is about to touch **before** touching it — with `.env.local` present that is production, same footgun as `npm run dev`. There is no admin UI. `create` also prints the sentence to tell the tester (below). **The tables only exist once migration 0019 has run on that database**, which happens at app boot or a Vercel build, not when the script runs; a database that has never booted this release answers `no such table`, and the script says so.
  - **The credits land on the tester's first OWN household** (#240): `createHouseholdForUser` calls `grantBetaPassCredits`, which claims the redemption with a guarded `UPDATE ... SET granted_at WHERE granted_at IS NULL` and only then calls `grantApartmentCredits` for `beta_passes.credits` — stamp-then-grant, the `recordPaymentOnce` posture, and an 8-way test pins exactly one grant. An invited joiner lands in someone else's household and gets nothing, which is right. **It grants with billing off too**: the counters are unread then, and if billing is switched on later a tester must already hold their credits or the purchase gate (`granted === 0`) would send them to the checkout they were promised never to see. Migration 0020 adds `granted_at`.
  - **Beta access is permanent, and it is said up front** (decided on #240): the "beta invitation is ready" notice and the script's `say:` line both state that neither data nor credits are taken back when the beta ends. Under E2EE nobody could recover a stranded household anyway. Refunds of beta credits do not exist, by decision, not omission.
- **The UI is the sign-in card only** (`src/app/login-form.tsx`, `access` + `notice` props, both passed from the server component `src/app/page.tsx`; the client never reads the variable). When closed it says it is a private beta, that sign-ups open "later this year", and links to the repo issues to ask for a place — no countdown, no invented waitlist figures, and a test asserts the absence. The three notices (`sign-up-refused`, `beta-ready`, `beta-invalid`) come from the query string the flows redirect back with. There is no contact address in the repo; the invite link points at GitHub issues until one exists.
