# Languages (#288)

Full reference. The rules for this area are in `.claude/rules/languages.md` (loaded when working on its files), with anything cross-cutting in AGENTS.md; this file holds the detail, the measurements and the history behind them.

- **Five interface languages, same URLs**: English, German, French, Italian, Spanish, through `next-intl` **without i18n routing**. Nothing about routes, `src/proxy.ts`, Auth.js callbacks, `/beta/<code>` or email links knows about a locale. Design: `docs/superpowers/specs/2026-10-20-i18n-design.md`.
- **Which language a request gets** (`resolveLocale`, `src/i18n/request.ts`): the `flatpare_locale` cookie, then (signed in, no cookie: a new device) `users.locale`, then `Accept-Language`, then English. The selector (`LanguageMenu`, in the nav bar) writes the cookie and, signed in, `PUT /api/account/locale`. `users.locale` is migration 0023 — account data in plaintext, like the display name.
- **`src/locales/` is a leaf module** (`locales.ts`: the five locales, regional tags, negotiation; `email-text.ts`: the emails' translator). It imports nothing from the app, so `src/lib`, `src/auth.ts`, `src/i18n` and components may all use it. **Nothing under `src/lib` and nothing at `src/` root may import `src/i18n`**: `src/i18n/request.ts` reads the session through `@/auth` and the database through `src/lib`, so either edge is a module cycle (both were hit, and fixed, in #288). Code outside `src/i18n` that needs a locale or translated text uses `src/locales`.
- **Swiss conventions, informal address**: German without ß, `de-CH` / `fr-CH` / `it-CH` / `es-ES` for every number and date and for `<html lang>`; *du / tu / tu / tú*.
- **Catalogues** are `messages/<locale>/<namespace>.json`, typed from English (`src/i18n/global.d.ts`). A new namespace goes in `NAMESPACES` (`src/i18n/messages.ts`), `global.d.ts` and a file per locale. `src/i18n/__tests__/catalogues.test.ts` fails when a locale lacks a key, a translation drops or adds a placeholder or a rich-text tag, a message is empty, or German contains ß.
- **Never concatenate translated fragments, never call `toLocaleString()` without a locale.** Plurals and interpolations are ICU messages; numbers and dates go through `useFormatter()` / `getFormatter()`. Pure modules that produce text (`src/lib/apartment-sort.ts`, `src/lib/map/points.ts`) take a text object from the caller rather than import translations.
- **Errors raised outside React** (the crypto flows, the store) keep an English message and are put into words on screen by code or by exact message (`useFlowErrorText`, `useStoreErrorDetails`). **Text the server sends is shown as sent** — moving every API error to a code is not part of #288.
- **Tests render through next-intl's real translator over the real catalogue**, English by default, without a provider (`src/test-setup.ts`). A test about language calls `setTestLocale("de")` (`src/i18n/__tests__/test-locale.ts`). Assert English text as before; the catalogue is what the app renders.
- **The PDF summary is written in the uploader's interface language** (PR 5). `parsePdf` sends `locale` with the multipart request; `/api/process/parse-pdf` passes it to `extractionPrompt(locale)` (`src/lib/parse-pdf.ts`), and anything that is not one of the five is English, not an error. The summary lands in the uploader's envelope, so a mixed-language household sees each summary in its author's language — accepted on the issue. The prompt itself stays in English and recognises German, French, Italian and Spanish listings; **the German patterns must stay**, and `parse-pdf.test.ts` asserts every pattern per language. `SHARED_LAUNDRY_PATTERN` carries the same four languages.
- **Still English, on purpose**: the owner's beta-request notice — it is an operator message.
- **The emails** (PR 4) read `messages/<locale>/emails.json` through `emailText(locale)` (`src/locales/email-text.ts`); the templates in `src/lib/email-templates.ts` take that `t` and stay pure. **The language is the recipient's own** (`users.locale`) when their account chose one, else the sender's — the inviter's or remover's request locale, passed by the route; for a magic link, the page it was asked from (`magicLinkLocale` in `src/auth.ts`) — else English. `scripts/beta-pass.mjs` reads the same JSON and takes `--locale`; keep `betaInvite.*` to plain `{name}` placeholders, since the script fills them without an ICU engine. `emails` is a server-only catalogue (`SERVER_ONLY_CATALOGUES`): not sent to the browser, but held to the same parity checks. The landing page, its metadata and the sketch notes are translated (PR 2), in `messages/<locale>/landing.json`.
- **The guide is one Markdown file per language**, `src/content/guide.<locale>.md` (PR 3), chosen by `languageOf(getLocale())` — so the path can only ever name one of the five. `guide-locales.test.tsx` holds each to the English guide's outline (headings per level, list items, table rows) and to the landing page's rules (one price, no zero-knowledge or open-source claim, no GitHub sign-in, no ß in German, no English paragraph left). **A change to the English guide is a change to all five**, and the UI labels it names must match each language's catalogue.
