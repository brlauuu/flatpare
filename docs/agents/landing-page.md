# Landing page (E7)

Full reference, moved verbatim from AGENTS.md. The always-on rules for this area are summarised in AGENTS.md; this file holds the detail, the measurements and the history behind them.

- **`/` is the landing page** (`src/app/page.tsx` composing `src/app/_components/landing.tsx`, with `LoginForm` passed in as the `signIn` slot). No routing change was needed: `src/proxy.ts` already redirects a signed-in session away from `/`, so the marketing page is unreachable for existing users and no auth flow touches it.
- **Redesigned in #301** from the Claude Design spec posted on that issue (neo-brutalism: blue & white light, black & yellow dark; the implementation decisions are the issue's second comment). Since #324 the landing page and the app share one palette: `--lp-*` tokens alias the app's theme tokens where the values match, and only landing-only values (video, sketch, map doodle, code, grid, chip and hosted-card lines) stay scoped to `.landing`. Archivo and IBM Plex Mono load in the root layout (`src/app/fonts.ts`); Caveat, used only by the hero sketch, loads in `landing-fonts.ts`. Tests stub both because `next/font` only runs under the Next compiler. See Theme (#324). The landing page and the app's nav bar render the **same** toggle (`src/components/theme-toggle.tsx`, #335): one button that flips light and dark, starting from the system preference until pressed. There is no separate "System" choice. Since #407 it is the bare sun or moon, no frame, and the language menu is the globe alone (its label names the language; not flags, since a language is not a country).
  - **The sign-in card is in a dialog** (`sign-in-dialog.tsx`, Base UI). `page.tsx` passes `openSignIn` whenever the query carries a notice (`?beta=ready`, `?signin=closed`, `?error=…`), so the sign-in flow's reports are visible without a click. The card itself is built in `page.tsx` exactly as before.
  - **`access` switches the hosted call to action**: closed (the hosted private beta) shows the beta-invite form and a `PRIVATE BETA` badge; open (a self-hoster's default) shows "Get started" / "Create your account", which open the dialog. A self-hoster's landing page never asks strangers for their email.
  - **While closed, the hosted card strikes through CHF 5 and shows "Free beta"** (#323), with one line that beta data and credits are kept — the same terms as the beta-ready notice and the `say:` line in `scripts/beta-pass.mjs`. Open shows the price plainly.
  - **The privacy section (`#privacy`, #323) is where every third party that sees plaintext is named**, and the hero's "Privacy first*" chip links to it. It holds `PRIVACY_CLAIM`, the "The exception, stated plainly" list (AI provider for PDFs — model providers with zero data retention on flatpare.com, Gemini by default self-hosted; Google Maps / OpenRouteService for one or two addresses, sent from our server with nothing that names the person; our server opening a listing link only to check it is online; the AI model searching the web for a listing whose link is missing or dead, #409), the map tiles (OpenFreeMap, which sees the browser's IP address and the area viewed), and the zero-knowledge disavowal ("private by design, but not zero-knowledge"). **The page does not name Vercel AI Gateway** (owner, #405); the zero-retention claim still rests on `AI_PROVIDER=gateway`. It applies to both paths, so it is not on the hosted card. **A new outbound service, or a change to `AI_PROVIDER` on the hosted deployment, means editing this section.**
  - **One logo pair everywhere** (#323): `ThemedLogo` (`src/components/themed-logo.tsx`) renders `flatpare_logo_blue.svg` / `flatpare_logo_yellow.svg` on the landing page, in the nav bar and on the sign-in card. `flatpare_logo.svg` remains only as the source of the PWA icons.
  - **The release notice** reads `FLATPARE_RELEASE_VERSION` / `FLATPARE_RELEASE_DATE`, which `next.config.ts` inlines at build time from CHANGELOG.md's newest version heading (`parseLatestRelease`, `src/lib/release.ts`, a leaf). Shown for 30 days after the release; dismissal is remembered per version in `localStorage`. No GitHub API call. `release.test.ts` parses the real CHANGELOG, so a heading format change that would silently turn it off fails there.
  - **The hero image is the real comparison grid**, `public/hero/compare-<locale>-{light,dark}.webp` — one per language and theme (#288), so the landing page shows the app in the reader's language — captured by `npm run build && npm run capture:hero` (`scripts/capture-hero.mjs`). The script starts its own production server on a throwaway SQLite file with encryption off and the shared password (empty env values override `.env.local`; it aborts unless the server logs `[db] local file`), signs in as a pre-created "Lena", and has Playwright answer `GET /api/apartments|ratings|locations` with invented Zürich listings and two fictional raters — so the pixels are the shipped components and nothing is written. **Re-run it whenever the grid's look changes**, or the landing page advertises an older app. `/hero/` is excluded in the proxy matcher like the logos.
  - **Still a placeholder:** the walkthrough video (`WALKTHROUGH_VIDEO_URL` / `WALKTHROUGH_DURATION` in `src/lib/site.ts`, `null` = "coming soon"). The video is a link to YouTube, not an embedded player, so the page loads nothing from Google until clicked.
  - **The pencil sketches** (`src/app/_components/hero-sketch.tsx`: the hero, plus two bands in "What's inside", #326) **are drawn at a fixed scale, 1920 units wide and centred**, so the marks keep their place beside the 1160px content column at every width. They used to scale with the window, which at 1920px cropped every mark out of the hero. They show from `xl` (1280px) up only; below that the content reflows and any fixed drawing lands on the text. The hero shows y 44–716 of its viewBox, and `hero-sketch.test.tsx` fails on a note outside that band. **No prices in the sketches**: SVG text is page text, and the one-price test would catch a mock rent.
- **Beta-invite requests (#301)**: the hosted card's form posts to `POST /api/beta-requests` (allow-listed in `src/proxy.ts`; `src/lib/beta-requests.ts`). One row per address, insert-or-ignore; the reply is `{ ok: true }` for a new address, a repeat and a tripped honeypot alike, so it cannot be used to learn who has asked. **`BETA_REQUESTS_PER_DAY = 50`, site-wide**, enforced by one conditional `INSERT ... SELECT ... WHERE count < cap ON CONFLICT DO NOTHING` (8-way concurrency test; not a transaction, see #225); while capped every request gets 429, known address or not. A new address emails the owner at `BETA_REQUEST_NOTIFY_EMAIL` (unset, or email off, = no notification; the row is stored either way). The address never reaches a log: unexpected errors log `scrubbedErrorLine` only, and a validation failure answers a fixed message instead of zod's issues, which can echo input. List them with `node scripts/beta-pass.mjs requests`; answer with `create --email`.
- **The copy rules are enforced by `src/app/__tests__/landing.test.tsx` (English) and `landing-locales.test.tsx` (all five languages), not by care.** The words live in `messages/<locale>/landing.json`. Before editing this page:
  - `PRIVACY_CLAIM` (`src/lib/site.ts`) is the spec's sentence **verbatim**; `landing.privacy.claim` in the English catalogue must equal it, and each language must render its own. Change it only if the spec changes, and change the constant, the five catalogues and the review together.
  - **In every language**: "zero-knowledge" (or a local equivalent) only inside the disavowal sentence; no local phrase for "open source" or "free software"; every price `CHF 5`; every disclosure in `DISCLOSURES` (the claim, the exception and its parts, the map tiles, the quota catch, no reset, beta permanence, the licence) rendered; no English sentence left in another language. A new legally meaningful sentence goes in `DISCLOSURES`.
  - **Never claim "zero-knowledge" unqualified.** The page disavows the term explicitly; a test fails on `is zero-knowledge` / `truly zero-knowledge`. The blind-proxy exception is real, so the unqualified claim would be false.
  - **Never call the project "open source".** The licence is **O'SAASY — source-available**: self-hosting and modification are fine, offering it to third parties as a competing hosted service is not. A test asserts the phrase never appears. (#187's issue text says "fully open source"; that is wrong.)
- **The domain is configuration.** `SITE_URL` (`src/lib/site.ts`) resolves from `NEXT_PUBLIC_SITE_URL`, then `VERCEL_PROJECT_PRODUCTION_URL`, then `http://localhost:3002`. `metadataBase`, canonical, Open Graph and Twitter tags all derive from it, so pointing a new domain at the deployment is an env-var change, not a code change.
- **One plan: CHF 5 ONCE — a one-time payment, not a subscription.** 10 people and a quota of 40 apartments per household; another CHF 5 adds another 40. No free tier, no second tier. Since #301 the price appears in the hosted card only; a test asserts every `CHF <n>` on the page is `CHF 5`, since a pricing page that contradicts itself is worse than one that says nothing.
  - **The 40 is a lifetime quota of apartments *processed* (#413; it was *added* before), not a cap on apartments *held*.** Deleting frees an active slot but does not refund the credit, and the page says so — that distinction is what a support complaint is made of. The active cap is also 40, so it only starts binding after a refresh purchase.
  - **Implemented in E6** (#188): `households.apartment_credits_granted` vs `apartments_ever_added`, added by migration 0017. The counter is monotonic, so delete-and-re-add no longer resets it. E5's `MAX_APARTMENTS` is the separate *active* cap and still counts current rows — see the Apartment credits (E6) section for how the two interact.
  - **The hosted deployment must set `MAX_MEMBERS=10` and `MAX_APARTMENTS=40`** to match the *active* cap. Those are env vars (E5) and unset means *unlimited*, so forgetting them does not fail loudly — it silently gives paying customers more than the page sells, and makes the page a false statement. Change the numbers in `src/app/_components/landing.tsx`, its test, and the deployment env together.
