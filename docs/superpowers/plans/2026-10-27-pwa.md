# PWA (#190) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Flatpare a proper installed phone app: receive shared PDFs and links, keep link-only shares as free drafts, help people install it, and fix the phone layout.

**Architecture:** Four PRs, each released on its own. PR 1 adds drafts: a fourth envelope table (`apartment_drafts`), routes, store methods and a "To add" strip with Paste link. PR 2 adds a narrow service worker that stashes shares in IndexedDB, plus manifest entries. PR 3 adds install help. PR 4 is the phone layout pass. This plan details PR 1 task by task. PRs 2 to 4 are outlined and get their own detailed plan when PR 1 has shipped, so they can build on what actually landed.

**Tech Stack:** Next.js 16 App Router, React 19, Drizzle + libSQL, zod, next-intl, Vitest + testing-library.

**Spec:** `docs/superpowers/specs/2026-10-27-pwa-design.md`

## Global Constraints

- Read AGENTS.md first. Vitest, not Jest. Tests in co-located `__tests__/`.
- Drafts are sealed like every row. AAD `"<householdId>:drafts:<id>"`. The server never parses an envelope. Writes go through `requireEnvelopeMode` and `requireCurrentKey`.
- `MAX_DRAFTS = 20` per household, enforced by one conditional `INSERT ... SELECT ... WHERE count < 20`. Never a `db.transaction` (#225).
- Creating a draft calls no outside service and consumes no credit.
- Every route: `requireMember()` -> `parseBody` -> work; unknown and foreign rows answer 404.
- No route under `src/lib` imports `@/components`. Pages never call `fetch` for household data; they use `useHouseholdData()`.
- New text goes in all five catalogues (`messages/<locale>/*.json`). German without ß, informal address. `catalogues.test.ts` must pass.
- Colours come from theme tokens only. Never combine `title-*` with `text-*`/`font-*`.
- No emoji in copy, docs or PRs.
- The dev database is remote: never run `npm run dev` without `TURSO_DATABASE_URL=`.
- Commits end with the attribution lines from the session; PR bodies end with the Claude Code line and the session URL.
- After the PR merges: release (minor), per AGENTS.md "Versioning and releases".

## Review Focus

1. **A rotation started from a tab that predates drafts.** An old client sends no `drafts` in the rotate request. The server must refuse (`409 Stale rows`) when the household has drafts, never leave a draft sealed under the old key. Test in Task 3.
2. **Pasting something that is not a web link.** Clipboard text like `javascript:alert(1)`, `homegate.ch/123` (no scheme), or a link inside a sentence. Only `http:`/`https:` URLs are accepted, the first one in the text is used, and nothing else becomes a clickable link. Test in Task 4 (`firstHttpUrl`).
3. **Completing a draft whose apartment save fails** (no credits, 402). The draft must stay. It is deleted only after `createApartment` resolves. Test in Task 6.
4. **The 21st draft.** The server answers 409 and the strip says the list is full, rather than a generic error. Tests in Task 2 (route) and Task 5 (UI message).
5. **A corrupt draft** (cannot be opened under the current key). It shows as a placeholder that can still be deleted, and does not break the apartments list. Test in Task 5.

Review Focus for PR 2 (each pinned by a test in the owning task):

4. **A share with only non-PDF files, or a link only in `text`.** Non-PDFs dropped and said so; the link found in `text` becomes a draft. Task 4.
5. **The add page opened twice for the same share** (a reload during review). The entry stays until the save completes, so a reload offers it again rather than losing it; it is deleted only after every item saved or the draft was created. Task 4.
